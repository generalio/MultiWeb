# 使用指南

MultiWeb 将跨平台的加载、导航和安全策略放在公共层，将原生视图与系统能力保留给对应平台。优先使用
`webview-compose`，只有不采用 Compose 时才直接依赖平台控制器。

## 1. 添加依赖

在项目仓库中配置可获取 MultiWeb 的 Maven 仓库后，Kotlin Multiplatform + Compose 项目只需在
`commonMain` 添加统一入口：

```kotlin
commonMain.dependencies {
  implementation("io.github.generalio.multiweb:webview-compose:<版本>")
}
```

`webview-compose` 会为 Android、iOS、Desktop 传递对应实现。JS/Wasm 仍使用同一公共调用方式，但只会打开
浏览器的新窗口或标签页，不能嵌入 WebView。

非 Compose 项目按 source set 依赖公共契约、扩展契约和目标平台实现：

```kotlin
commonMain.dependencies {
  implementation("io.github.generalio.multiweb:webview-api:<版本>")
  implementation("io.github.generalio.multiweb:webview-extension-api:<版本>")
}

androidMain.dependencies {
  implementation("io.github.generalio.multiweb:webview-android:<版本>")
}

iosMain.dependencies {
  implementation("io.github.generalio.multiweb:webview-ios:<版本>")
}

desktopMain.dependencies {
  implementation("io.github.generalio.multiweb:webview-desktop:<版本>")
}

jsMain.dependencies {
  implementation("io.github.generalio.multiweb:webview-browser:<版本>")
}

wasmJsMain.dependencies {
  implementation("io.github.generalio.multiweb:webview-browser:<版本>")
}
```

`webview-test-fixtures` 仅供本仓库的测试与示例使用，不是对外依赖。

## 2. KMP Compose 快速接入

在 `commonMain` 创建初始化参数、Controller 和视图。Controller 会随 Composition 自动释放；Android 的前后台
状态也会由 Compose 入口自动转发：

```kotlin
@Composable
fun WebPage() {
  val initialization = remember {
    WebViewInitialization(
      webViewConfig = WebViewConfig(
        javaScriptEnabled = true,
        // Desktop JCEF 无法按单个浏览器关闭这两项，跨平台配置需要显式确认。
        thirdPartyCookiesEnabled = true,
        persistentSessionEnabled = true,
        allowedHosts = setOf("example.com"),
      ),
      navigationPolicy = DefaultNavigationPolicy,
    )
  }
  val controller = rememberWebViewController(
    initialization = initialization,
    hostCallbacks = WebViewHostCallbacks(
      onExternalNavigation = { request ->
        // 调用方用自身的路由、Intent 或系统 API 处理 request.url。
      },
    ),
  )

  LaunchedEffect(controller) {
    controller.load(WebRequest("https://example.com"))
  }

  WebView(
    controller = controller,
    modifier = Modifier.fillMaxSize(),
  )
}
```

`WebView(...)` 在 Android、iOS 与 Desktop 嵌入原生视图；JS/Wasm 不绘制内容。不要把一个 Controller 跨
Activity、UIViewController 或桌面窗口复用。

### Desktop 运行时初始化

JCEF 的 `CefApp` 是进程级资源，必须由桌面宿主在首次调用 `rememberWebViewController` 前创建并只注入一次。
MultiWeb 会在浏览器和 Client 均关闭后回调 `onBrowserClosed`，但绝不会自动调用 `CefApp.dispose()`：

```kotlin
val cefApp = CefAppBuilder().build()

DesktopWebViewRuntime.initialize(
  cefApp = cefApp,
  onBrowserClosed = {
    // 确认应用中没有其他浏览器后，再由宿主销毁 cefApp。
  },
)
```

请在桌面应用的启动代码中调用，而不是放入可重组的 Composable。窗口关闭时应调用 Controller 的 `dispose()`；
等待 `onBrowserClosed` 后再结束 JCEF 进程。

## 3. 非 Compose 平台接入

非 Compose 宿主可直接创建各平台控制器。所有控制器都接收同一个 `WebViewInitialization`，因此安全配置、
导航策略和扩展无需按平台重复定义。

### Android

在主线程创建 `AndroidWebViewController`，将 `controller.view` 加入 View 层级，并在宿主生命周期中转发暂停、
恢复和销毁事件：

```kotlin
val controller = AndroidWebViewController(
  context = applicationContext,
  initialization = initialization,
  onExternalNavigation = { request ->
    // 调用方决定是否通过 Intent 或业务路由打开 request.url。
  },
)

container.addView(controller.view)

override fun onPause() {
  controller.onHostPause()
  super.onPause()
}

override fun onResume() {
  super.onResume()
  controller.onHostResume()
}

override fun onDestroy() {
  controller.dispose()
  super.onDestroy()
}
```

需要自定义 `WebView` 子类时，通过 `AndroidWebViewFactory` 传入 `webViewFactory`。工厂只负责创建未附着、未配置
的实例；不得在其中设置 `WebViewClient`、`WebChromeClient`、`addJavascriptInterface` 或自行 `destroy()`。

Android 使用进程级 Cookie 存储，目前不支持 `persistentSessionEnabled = false`，此配置会在创建控制器时失败。
组件会启用同源 DOM Storage，以兼容依赖 `localStorage` 与 `sessionStorage` 的 HTTPS 页面；它不会放宽 HTTP
混合内容、本地文件访问或无手势自动播放等限制。

### iOS

在主线程创建 `IosWebViewController`，将 `controller.view` 加入 UIKit 层级；UIKit 负责应用前后台切换，视图不再
需要时调用 `dispose()`：

```kotlin
val controller = IosWebViewController(
  initialization = initialization,
  onExternalNavigation = { request ->
    // 由 UIViewController、UIApplication 或应用路由处理 request.url。
  },
)

view.addSubview(controller.view)
```

`persistentSessionEnabled = false` 会使用 WebKit 的非持久化数据存储。第三方 Cookie 不由单个 WKWebView 精确
控制，组件保留 WebKit 的系统级隐私策略，不会尝试绕过 Intelligent Tracking Prevention。

### Desktop

在 Swing EDT 创建 `DesktopWebViewController`，把 `controller.view` 放入 Swing/AWT 容器。进程级 `CefApp` 的创建、
配置和最终销毁都属于宿主职责：

```kotlin
val controller = DesktopWebViewController(
  cefApp = cefApp,
  initialization = initialization,
  onExternalNavigation = { request ->
    // 由宿主决定外部导航的处理方式。
  },
  onBrowserClosed = {
    // 原生浏览器关闭且 Client 释放后通知宿主。
  },
)
```

JCEF 不能按单个浏览器可靠关闭 JavaScript、第三方 Cookie 或持久化会话。为了避免静默采用进程默认值，Desktop
控制器要求这三项均显式为 `true`；更严格的 JCEF 策略必须在创建 `CefApp` 前由宿主配置。

### JS 与 Wasm

直接使用 `BrowserWebViewController`，或采用第 2 节的 Compose 统一入口。允许的 URL 会由浏览器在新窗口或
标签页打开，浏览器可能因弹窗策略阻止该操作：

```kotlin
val controller = BrowserWebViewController(
  config = WebViewConfig(allowedHosts = setOf("example.com")),
  navigationPolicy = DefaultNavigationPolicy,
)
controller.load(WebRequest("https://example.com"))
```

此平台不能嵌入浏览器，也不能管理浏览器的 Cookie、缓存与 JavaScript 权限。`clearSession()` 会抛出
`UnsupportedOperationException`；不支持页面扩展和 JS 桥。

## 4. 公共 API 参考

### 4.1 `WebViewInitialization`

`WebViewInitialization` 将跨平台共用的配置集中为一个不可变对象：

| 属性 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `webViewConfig` | `WebViewConfig` | `WebViewConfig()` | 安全能力、会话和主机白名单。 |
| `navigationPolicy` | `NavigationPolicy` | `DefaultNavigationPolicy` | 决定每次导航是内嵌、取消还是交由宿主。 |
| `extensions` | `List<WebViewExtension>` | `emptyList()` | 页面事件、下载、宿主 UI 请求和 JS 桥扩展。 |

初始化参数变更时，`rememberWebViewController` 会释放旧 Controller 并创建新实例。因此应使用 `remember` 保持
不随重组变化的初始化对象。

### 4.2 `WebViewConfig`

所有高风险配置默认按最小权限关闭：

| 属性 | 默认值 | 行为与平台差异 |
| --- | --- | --- |
| `javaScriptEnabled` | `false` | 是否允许网页 JavaScript。Android 与 iOS 可关闭；Desktop 必须为 `true` 才能创建 JCEF 控制器；JS/Wasm 由用户浏览器控制。 |
| `thirdPartyCookiesEnabled` | `false` | Android 可按 WebView 设置；iOS 由 WebKit 系统隐私策略决定；Desktop 必须为 `true` 才能创建控制器；JS/Wasm 由浏览器控制。 |
| `fileAccessEnabled` | `false` | 是否允许 `file://` 导航。仅在确有本地内容需求时开启，并自行限制文件来源。 |
| `persistentSessionEnabled` | `true` | 是否持久化 Cookie、缓存等会话。iOS 为 `false` 时使用非持久化存储；Android 与 Desktop 当前不支持隔离临时会话，会拒绝该配置；JS/Wasm 不可控。 |
| `allowedHosts` | 空集合 | 内嵌页面精确主机名白名单；空集合只由导航策略决定。无通配符，`example.com` 不匹配 `m.example.com`。 |

`allowedHosts` 是额外的控制层，不会替代 `NavigationPolicy`。白名单非空时，平台控制器会先执行精确匹配，
然后再执行导航策略。JS 桥同样只匹配 HTTPS、精确主机与默认端口 `443`；不会注入到 HTTP、带凭据或非默认端口页面。

### 4.3 导航策略

`NavigationPolicy` 接收 `NavigationRequest(url, isMainFrame, isUserInitiated)`，返回：

| 返回值 | 结果 |
| --- | --- |
| `NavigationDecision.Allow` | 在当前 WebView 继续导航。 |
| `NavigationDecision.Cancel` | 阻止本次导航。 |
| `NavigationDecision.OpenExternally` | 回调给 `onExternalNavigation`，由宿主决定如何打开。 |

`DefaultNavigationPolicy` 仅允许以 `https://` 开头的地址。需要外部打开自定义 Scheme 或 HTTP 链接时，应显式定义
策略，而不是放宽默认策略：

```kotlin
val policy = NavigationPolicy { request ->
  when {
    request.url.startsWith("https://") -> NavigationDecision.Allow
    request.isUserInitiated && request.url.startsWith("mailto:") -> {
      NavigationDecision.OpenExternally
    }
    else -> NavigationDecision.Cancel
  }
}
```

`OpenExternally` 不会自动启动 Android Intent、`UIApplication` 或桌面系统浏览器；这是调用方必须显式实现的宿主行为。

### 4.4 `WebViewController`

| 成员 | 说明 |
| --- | --- |
| `state` | 当前状态快照，包含 URL、标题、加载进度、历史记录能力及最近错误。 |
| `load(WebRequest)` | 加载 URL；`WebRequest.headers` 是附加请求头，JS/Wasm 浏览器模式不支持附加请求头。 |
| `reload()` | 重新加载当前页面；JS/Wasm 会再次尝试打开当前 URL。 |
| `goBack()` / `goForward()` | 在平台历史记录中前进或后退；JS/Wasm 无嵌入历史记录。 |
| `stopLoading()` | 停止当前加载；JS/Wasm 无进行中的嵌入加载。 |
| `clearSession()` | 清理当前平台可管理的 Cookie、缓存等数据；JS/Wasm 会抛出 `UnsupportedOperationException`。 |
| `dispose()` | 释放原生资源。可重复调用；首次释放后，除 `dispose()` 外的操作均会抛出 `IllegalStateException`。 |

`WebViewState` 字段为 `url`、`title`、`loadingProgress`（范围 `0f..1f`）、`isLoading`、`canGoBack`、
`canGoForward` 和 `error`。`WebError` 包含 `category`、`description` 与可选的 `failingUrl`；错误类别为
`Navigation`、`Network`、`Ssl`、`RenderProcess`、`Unknown`。

## 5. 扩展与受限 JS 桥

### 5.1 `WebViewExtension`

将扩展放入 `WebViewInitialization.extensions`。扩展不能替换平台内部 Client、导航策略或安全校验：

| 回调 / 属性 | 用途 |
| --- | --- |
| `scriptBridges` | 注册仅对可信 HTTPS 主机开放的 JS 桥。 |
| `onPageStarted` / `onPageFinished` | 获取主文档加载开始、完成及可选标题。 |
| `onPageError` | 获取不可恢复的页面错误。 |
| `onDownloadRequested` | 接收下载请求；具体下载、权限和保存路径由宿主决定。 |
| `onContextAction` | 接收链接或图片长按等上下文操作。 |
| `onHostUiRequest` | 接收宿主级 UI 请求，例如 `HostUiRequest.SetFullscreen`。 |

各平台无法提供的事件不会回调，调用方需为重要行为设计宿主侧降级方案。JS/Wasm 的 `webview-browser` 不安装扩展。

### 5.2 平台扩展能力矩阵

| 平台 | `onDownloadRequested` | `onContextAction` | 说明 |
| --- | --- | --- | --- |
| Android | 支持：系统 `DownloadListener` 提供 URL、建议文件名、MIME 类型与长度。 | 支持：链接和图片长按。 | 回调不等于已保存；文件下载、存储权限与目标路径由宿主处理。 |
| iOS | 支持：仅不可由 WebKit 渲染的主框架 MIME 响应。控制器派发事件后取消该导航。 | 支持：iOS 13+ 系统上下文菜单中的链接长按。 | WebKit 原生菜单不公开图片 URL，因此图片长按不会回调；宿主收到下载事件后自行执行下载与保存。 |
| Desktop | 支持：JCEF 派发事件后继续其默认下载流程。 | 支持：链接和图片上下文菜单。 | 保存位置与权限由 JCEF/宿主运行环境决定。 |
| JS / Wasm | 不支持。 | 不支持。 | 仅在浏览器新窗口或标签页打开 URL，不安装扩展或管理浏览器权限。 |

不要将扩展回调视为文件已保存或用户已授权。特别是 iOS 下载回调只提供 WebKit 已验证的响应元数据，宿主仍应校验
URL、重定向、MIME 类型、文件大小和最终保存位置。

### 5.3 自定义 `ScriptBridge`

`ScriptBridge` 包含全局名称 `name`、精确可信主机 `allowedHosts` 和处理函数 `handle`。它只应暴露少量、
可序列化且已在宿主校验过的方法；禁止把任意 Kotlin/Java/Objective-C 对象直接暴露给网页。

需要在网页侧获得 Promise 响应时，实现 `ScriptBridgeWithFacade` 并声明允许的方法名。平台会创建单独的内部
消息通道，向网页暴露受限门面，而不是暴露原生对象。

### 5.4 兼容旧网页的 `NativeWebViewBridgeExtension`

`NativeWebViewBridgeExtension` 为旧的 `window.AndroidWebView` 调用形式提供跨平台封装。它只负责把请求转换为
`NativeWebViewBridgeRequest`；账号、路由、传感器、下载、全屏和执行脚本均必须由应用实现 `NativeWebViewBridgeHost`
决定：

```kotlin
val bridge = NativeWebViewBridgeExtension(
  allowedHosts = setOf("app.example.com"),
  host = NativeWebViewBridgeHost { request ->
    when (request) {
      is NativeWebViewBridgeRequest.SetFullscreen -> {
        // 由 Android Activity、UIViewController 或桌面 Window 切换全屏。
        NativeWebViewBridgeResult.Success()
      }
      is NativeWebViewBridgeRequest.SaveImage -> {
        // 由宿主做二次 URL 校验、用户确认、权限申请和下载保存。
        NativeWebViewBridgeResult.Success()
      }
      else -> NativeWebViewBridgeResult.Failure("unsupported_operation")
    }
  },
)
```

桥支持的网页方法为 `savePic`、`onLoad`、`initSensor`、`jump`、`exeJs`、`toast`、`getStu`、`isDark`、
`setFullscreen`、`getSystemBarInsets`、`getToken`。全部统一返回包含 `isSuccess`、`payload` 和可选 `errorCode` 的
Promise 响应对象，网页应使用 `await`：

```javascript
const { payload: token } = await window.AndroidWebView.getToken();
await window.AndroidWebView.setFullscreen(true);
await window.AndroidWebView.savePic("https://cdn.example.com/poster.png");
```

宿主应拒绝不支持的请求并返回稳定错误码，不要假装成功。图片保存必须自行限制可信来源、重定向、MIME 类型和大小，
并要求用户确认；令牌、脚本执行和应用内跳转都属于高风险业务能力，应额外做权限与参数校验。

## 6. 常见限制

- `webview-compose` 仅统一 Compose 接入，不替应用处理外部链接、系统权限、路由或 JCEF 的进程生命周期。
- Android、iOS 与 Desktop 的原生运行时行为仍应在真实设备、模拟器或桌面环境验证。
- JS/Wasm 只负责经策略允许的 URL 跳转，不能伪装为可控的嵌入式 WebView。
- 更多模块边界和安全原则见[架构说明](架构说明.md)。
